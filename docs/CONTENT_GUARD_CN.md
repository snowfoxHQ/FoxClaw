# 内容闸门与敏感词表

这层只做一件事：在**用户请求**和**模型输出**两端做确定性判定，命中就用一句固定话术切断。

它不调用模型、不做语义理解，也不替代平台审核或人工审核。提示词层负责让模型自己不越线，这一层负责在模型或用户绕过提示词时守住下限。

## 三层判定来源

| 来源 | 位置 | 可配置 | 覆盖范围 |
|---|---|---|---|
| 内置规则 | `foxclaw/core/content_guard.py` 的 `_BUILTIN_RULES` | 否（只能整体 `off`） | 六类**请求型教唆**：制毒制爆、诈骗洗钱、入侵他人系统、伪造证件、自杀方法、未成年性内容 |
| 外部词表 | `FOXCLAW_CONTENT_LEXICON` 指向的文件 | 是 | 由你决定，政治 / 色情 / 暴力等大类都在这一层挂 |
| 提示词 | `KERNEL_PROMPT` 【八、内容边界】 | 改代码 | 软约束，负责语气与拒绝范式 |

内置规则刻意写得很窄——必须同时出现「动作词 + 对象」才算命中，比如「怎么制作炸药」命中，「我买了一本讲炸药发展史的书」不命中。目标是开箱即用且不打断正常对话，不是覆盖所有违规表达。

**数万条量级的大类词表不内置**：监管口径会变、误伤面由部署方决定、词表体积也不该压进代码。要不要挂、挂哪几类，是部署决策，交给你。

## 默认行为

装好就生效，不需要配置：

- 模式默认 `enforce`
- 只有内置规则在跑（没挂词表时）
- 输入命中 → 直接返回固定话术，**请求不进模型**
- 输出命中 → 整段替换为固定话术，不保留任何原文片段
- 流式输出命中 → 在命中点停止继续下发

固定话术跟随输入语种，只有中英两种：`我们换个话题聊聊吧。` / `Let's talk about something else.`

不解释、不延伸、不反问、不给替代方案。拒绝本身不能变成信息泄漏或继续纠缠的入口。

## 三档模式

```bash
FOXCLAW_CONTENT_GUARD_MODE=enforce   # 默认：真拦截
FOXCLAW_CONTENT_GUARD_MODE=audit     # 只记录不拦截，用于观察误伤
FOXCLAW_CONTENT_GUARD_MODE=off       # 完全关闭
```

写错的值会回退到 `enforce`（宁可多拦，不会静默失效）。

`audit` 档的命中记录打在**进程 stdout** 上：

```
[Foxclaw] ⚠ 内容命中(未拦截): category=politics word='某某'
```

只有 `audit` 会打印。`enforce` 档命中是静默的——需要审计留存的话，在调用侧接 `Decision.to_dict()`，或者先跑一段 `audit` 采集基线。

## 配置写在哪

两条路，效果不同：

- **`.env`（推荐）**：API 服务在导入包之前加载 `.env`，写进这里即可生效。注意 `.env` 里的空值视为未配置，不会覆盖系统环境变量。
- **系统环境变量**：SDK 里直接用 `Foxclaw()` 时 `.env` 不会被自动加载，必须在进程启动前设好环境变量。

`.env` 加载可以关掉：`FOXCLAW_SKIP_DOTENV=1`。

## 词表格式

一行一条，UTF-8，`#` 开头为注释：

```
# 词<TAB>类别，类别可省略
某词	politics
另一个词	sexual
不带类别的词
```

规则细节（都来自加载器实现，不是约定俗成）：

| 项 | 行为 |
|---|---|
| 分隔符 | `词<TAB>类别`；没有 TAB 时整行是词，类别取 `platform` |
| 注释 | `#` 开头整行跳过 |
| 空白与标点 | 每个词先过一遍 `compact()`：去空白、去中英标点、全半角归一、转小写 |
| 长度 | `compact()` 之后少于 2 个字符的**直接丢弃**（单字词误伤太大，且几乎拦不住真违规） |
| 同词多类别 | 允许；扫描结果按 `(类别, 词)` 去重，命中取第一个 |
| 坏行 / 读不到的文件 | 静默跳过，不会让服务起不来 |
| 生效时机 | **进程启动时建索引，改词表要重启**；没有热重载 |

路径用**绝对路径**最稳。相对路径按进程工作目录解析，systemd 之类的工作目录可能不是项目根。

改完词表重启，在启动后确认加载条数——可以先手工载入一次：

```bash
python -c "from foxclaw.core.content_guard import ContentGuard; print(ContentGuard().lexicon_size)"
```

打印 0 就是没读到。

## 从第三方词库转换

现成的敏感词库（如 `houbb/sensitive-word` 的 6 万条主词库、各类按政治/色情/暴力分好类的版本）格式各不相同：有的单文件纯词，有的一个类别一个文件，有的 GBK 编码，有的同一批词里混着 `敏感词`、`敏 感 词`、`ＳＥＮＳＩＴＩＶＥ` 三种写法。

`tools/build_content_lexicon.py` 负责转换。**这个脚本在仓库里，不随 wheel 分发**——`pip install` 的用户需要从 GitHub 仓库取：

```bash
# 单文件主词库，全部归到 platform 类别
python tools/build_content_lexicon.py sensitive_word_dict.txt -o content_lexicon.txt

# 分类词库：文件名含中文就用文件名当类别（政治类.txt → 政治类）
python tools/build_content_lexicon.py dict/*.txt -o content_lexicon.txt

# 自己挑类别：只留需要的那几类
python tools/build_content_lexicon.py dict/*.txt --exclude 政治类,色情类 --exclude "暴力*" -o content_lexicon.txt

# 单文件但想指定类别名
python tools/build_content_lexicon.py ads.txt --category ads -o content_lexicon.txt
```

它做四件事：

1. **自动判编码**：先 `utf-8-sig` 后 `gb18030`。国内下载的词库不少是 GBK，而加载器固定按 UTF-8 读并忽略坏字节——这步不做，词会在挂载后静默缺失。
2. **转换期归一化**：用加载器同一个 `compact()`，重复写法当场合并，不让自动机被同一词的三种写法撑大。
3. **按类别筛选**：`--include` / `--exclude` 支持通配符，逗号分隔，可重复。
4. **回读验证**：转换完用真正的 `ContentGuard` 载入输出文件，抽样扫描确认能命中；不过关直接退出码 1。

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-o, --output` | `content_lexicon.txt` | 输出路径 |
| `--category` | `platform` | 文件名不含中文时使用的类别名 |
| `--include` / `--exclude` | 无 | 类别筛选，支持 `通配*` |
| `--encoding` | `auto` | 可强制指定 |
| `--min-len` | `2` | 短于该长度丢弃（与加载器一致） |
| `--max-len` | `0` | 长于该长度丢弃，0 为不限 |
| `--sample` | `5` | 验证抽样条数 |
| `--no-verify` | 关 | 跳过载入验证 |

六万条规模的词表，转换加快载入验证在半秒量级。

转换产物已在 `.gitignore` 里排除（`/content_lexicon*.txt`），不要提交进仓库。

## 挂上之前先跑 audit

**这是最容易跳过、后果最直接的一步。**

六万条量级的词表里必然有大量双字词。直接挂 `enforce`，正常的订单讨论、书稿审阅、医学问答都可能被切断——命中就整段替换，用户不知道发生了什么，只知道助手突然开始说「我们换个话题聊聊吧。」

建议流程：

1. 挂词表，`FOXCLAW_CONTENT_GUARD_MODE=audit`
2. 正常用几天，收集 stdout 里的命中行
3. 逐条看 `category` 和 `word`：哪些是该拦的，哪些是误伤
4. 误伤多的类别用 `--exclude` 摘掉，或者换更长的词条重新生成
5. 确认可接受后再转 `enforce`

没有白名单机制。压制误伤的手段只有三个：少挂类别、用更长的词条、把 `--min-len` 调高。

## 精度说明

这一层是**限速带**，不是墙。明确不处理：

- 拼音、谐音、拆字、外文转写（追下去是无底洞，且误伤率更高）
- 图片、语音、附件正文
- 跨轮诱导（把一句话拆成三轮说）
- 知识库导入的书籍、法律条文、医学教材内容

最后一条是刻意的：**过滤器只挂在「用户请求」与「模型输出」两端**，不碰用户自己的资料。历史书里写「炸药配方」不该导致这本书导入失败。

流式输出有个固有限制：命中那一刻只能保证之后不再吐字，**已经下发的前缀收不回来**。非流式路径是整段替换，没有这个问题。

## 排查清单

| 现象 | 检查 |
|---|---|
| 完全不拦 | `FOXCLAW_CONTENT_GUARD_MODE` 是不是 `off`；环境变量有没有真的进进程 |
| 内置规则生效、词表不生效 | `ContentGuard().lexicon_size` 是否为 0；路径是相对还是绝对；文件编码 |
| 挂了词表后某些词没拦到 | 词是不是 `compact()` 后不足 2 字被丢了；词表里是不是有空格被当成了词的一部分 |
| 改了词表没变化 | 进程没重启；索引是启动时建的 |
| 正常对话被切断 | 词表里双字词太多，先降 `audit`，或摘掉该类 |

## 和提示词层的关系

两层职责不同，都要有：

- 提示词层（`KERNEL_PROMPT` 【八】+ `behavior.yaml` 的 `no_harmful_content`）负责语义边界：什么算违规、拒绝时怎么说话、用户的资料和指令怎么区分。
- 代码层（本文件）负责确定性下限：词表命中就是命中，不经过模型判断。

只做提示词，模型被绕过去就没有兜底；只做代码，边界场景的取舍全靠词表，回答会变得机械。两层一起，才是「模型自己知道分寸，同时越线时有保险」。

## 责任边界

仓库不附带任何政治 / 色情 / 暴力词表。是否挂载、挂哪几类、跑哪一档,全部由部署方决定,项目不预设口径。

这一层做的是归一化后的字符串匹配,不保证覆盖率,也不构成内容审核或合规服务。对外提供服务时的内容合规责任在部署方自身。软件按“现状”提供,详见 [LICENSE](../LICENSE)。
